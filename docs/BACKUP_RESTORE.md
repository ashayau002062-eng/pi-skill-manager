# 备份、迁移与恢复

先分清不同备份的范围；存在备份不代表能自动迁移到新电脑。

| 类型 | 保存什么 | 不保存什么／限制 |
|---|---|---|
| 单 Skill ZIP | 原文、普通附件、空目录 | 不含 Pi 设置和管理器整理数据；不含 .git／node_modules |
| 多选 ZIP | 多个 Skill 的独立子目录与清单 | 不是单 Skill 导入格式，需人工逐个恢复 |
| 整理信息 JSON | 收藏、分组、标签、备注、视图、核对用位置 | 无正文、Pi 配置、添加时间和本地未知扩展字段；最多 1 MiB／1000条／30视图 |
| 编辑历史 | 保存前原文件 | 位于 agent-dir/skill-manager-backups；不自动清理 |
| 回收站归档 | 被删除的完整 Skill／独立 Markdown及记录 | 不是额外异地备份；永久清理会删除它 |

## 日常备份

1. 用单 Skill 或多选 ZIP 备份内容。
2. 用「整理备份…」单独导出整理 JSON。
3. 若需要灾难恢复，停止管理器与其他 Pi 配置写入后，自行备份实际 agent-dir 下的管理器偏好与编辑历史、各标准 skills roots 和对应归档目录；Pi settings 也要单独备份。
4. 把私密备份放在受保护的位置。不要推入本源码仓库：Skill、隐藏附件、备注、路径、settings 和 Pi 认证文件可能含私密信息。不要为备份工具而分享 auth.json／密钥。

## 恢复原机器／原路径

优先使用网页历史恢复和回收站恢复，它们检查版本／目标冲突并备份当前内容。手工恢复前先停止所有相关写入，核对原位置和记录；已有目标绝不直接覆盖。

整理 JSON 导入先预览，默认合并（追加收藏／标签、只补空组／备注）；「覆盖匹配项」只对匹配项覆盖，不动未匹配记录和未知字段。修改文件／模式后需重做预览；取消无写入。

整个设置文件的人工恢复可能覆盖其他 Pi 配置，不能用一次模糊复制来代替核对。设置恢复后在 Pi /reload，必要时新对话。

## 换电脑或移动目录

位置 ID 来自实际路径，**整理 JSON 只精确匹配当前发现的位置 ID**，不会按同名猜测，也不从 JSON 路径读写文件。换目录／机器可能显示未匹配并跳过；此版本不承诺自动重定位整理数据。

先恢复内容到你选择的位置，再检查原生发现、同名冲突、启用状态和未匹配项，必要时人工重建收藏／分组／备注。多选 ZIP 可手工解压，核对清单和独立 Markdown 标志后逐个处理；不要把仓库压缩包直接作为单 Skill 导入。

推荐先用虚构 Skill 在隔离目录做一轮「导出→导入→查看原文附件→整理预览」，再处理重要真实数据。不要用个人文件做破坏性验收。
